# Profimonsters · Операционные показатели

Дашборд для руководителя: динамика 17 показателей по проектам, сравнение с прошлым периодом,
рейтинг проектов, ручной ввод, импорт CSV/Excel. Next.js 15 + React + TypeScript + Tailwind + Recharts.

## Запуск

Нужен Node.js 20 или 22.

```bash
npm install
npm run dev          # http://localhost:3000
# продакшен:
npm run build && npm start
```

Данные сохраняются в `data/records.json` (создаётся при первой записи). Пока база пустая,
сайт открывается в демо-режиме с вымышленными проектами — переключатель «Рабочие данные / Демо» в шапке.

Другие команды:

- `npm test` — проверка расчётов (свёртка, сравнение периодов, дубли, импорт);
- `npm run typecheck` — проверка типов;
- `npm run build:standalone` — та же страница одним HTML-файлом (`dist/`), без сервера.

## Размещение на Netlify

В проекте уже есть `netlify.toml`. На Netlify записи хранятся в Netlify Blobs — это включается само,
настраивать базу не нужно. Подключите репозиторий GitHub в Netlify (Add new project → Import an existing project),
настройки сборки подставятся из `netlify.toml`.

## Google Таблицы

1. Лист с колонками `Дата · Проект · Показатель · Значение · План · Примечание` (как шаблон импорта).
2. В таблице: Файл → Поделиться → Опубликовать в интернете → нужный лист → CSV → Опубликовать. Скопировать ссылку.
3. В Netlify: Project configuration → Environment variables → `GOOGLE_SHEET_CSV_URL` = ссылка. Затем Deploys → Trigger deploy.
4. Данные подтягиваются кнопкой «Обновить» и автоматически раз в час (`netlify/functions/sync-google-sheet.mts`).

Строки таблицы перезаписывают записи с той же датой, проектом и показателем; записи, внесённые на сайте вручную, не удаляются.

## Структура

| Папка | Что внутри |
|---|---|
| `src/config/metrics.ts` | Каталог показателей: названия и описания из «Данные для Дашборта.xlsx», единица, направление оценки, свёртка за период. Менять допущения — здесь. |
| `src/domain/` | Модель записи, ключ уникальности (дата + проект + показатель), проверки полей. |
| `src/analytics/` | Все расчёты: свёртка, сравнение, рейтинг, план, ряды для графика, форматирование чисел. |
| `src/filters/` | Периоды (быстрые периоды, предыдущий сопоставимый), фильтры. |
| `src/data/sources/` | Слой данных: общий интерфейс `DataSource` и реализации — демо, база сайта (API), хранилище браузера, база опубликованной версии. |
| `src/data/import/` | Чтение CSV/Excel, проверка строк, шаблон и выгрузка. |
| `src/server/repository/` | Хранилище на сервере: Netlify Blobs на Netlify, JSON-файл в остальных случаях. Схема для PostgreSQL — `db/schema.sql`. |
| `src/server/connectors/` | Заготовки внешних источников: Google Таблицы, amoCRM, API, внешняя БД. |
| `src/components/` | Интерфейс. Компоненты только отображают результаты расчётов. |
| `src/app/api/` | API: `GET/POST /api/records`, `DELETE /api/records/:id`, `POST /api/records/bulk`, `GET /api/connectors`. |

## Допущения (формулы в исходном файле не заданы)

- Значения вводятся готовыми; дашборд не вычисляет одни показатели из других.
- За период: лиды, смены, увольнения, выручка, коэффициент — сумма; среднедневной выход, конверсии,
  текучка, жизнь новичка, стоимость 1 смены, NPS — среднее; активный штат, потребность, дебиторка — последнее значение.
- Снижение — хороший результат для увольнений, текучки, стоимости первой смены и дебиторки; для потребности направление не оценивается.
- «Без изменений» — меньше 1 % (для процентов и NPS — меньше 0,5 п.).
- Сравнение: с периодом той же длины перед текущим; «текущий месяц» — с тем же числом дней прошлого месяца.
- Пропуски на графике — разрыв линии; соединить их можно галочкой «Соединять пропуски».

## Как подключить внешний источник

1. Реализовать `fetchRecords(range)` в `src/server/connectors/index.ts` — вернуть массив `RecordDraft`.
2. Задать переменные окружения (см. `.env.example`).
3. Записи проходят ту же проверку (`validateDraft`) и сохраняются через `bulk` с защитой от дублей.

Интерфейс и расчёты при этом не меняются.
